# 로컬 시험장

이 문서는 처음 받는 사람이 자신의 컴퓨터에서 앱을 직접 눌러 보면서 시험할 수 있도록 만든 가장 쉬운 경로입니다.

이 방식은 다음 특징이 있습니다.

- Docker만 있으면 됨
- 샘플 사용자와 샘플 게임이 자동 생성됨
- 관리자 계정도 자동 생성됨
- 종료할 때 mock DB와 컨테이너를 같이 지워서 흔적 없이 정리 가능

## 언제 이 방식을 쓰나

- "일단 앱이 어떻게 돌아가는지 보고 싶다"
- "관리자 화면을 눌러보고 싶다"
- "실제 행사 전에 운영 흐름을 연습하고 싶다"
- "로컬 개발 환경을 세팅하기 전에 먼저 확인하고 싶다"

코드를 수정하면서 개발할 목적이면 [로컬 개발](./local-development.md)을 보세요.

## 준비물

- Docker Desktop 또는 Docker Engine

이 방식은 아래가 없어도 됩니다.

- pnpm
- MongoDB 직접 설치
- Node.js 개발 환경

## 1. 시험장 시작

프로젝트 루트에서 아래를 실행하세요.

```bash
./scripts/local-lab-up.sh
```

처음 실행이라면 이미지 빌드 때문에 몇 분 걸릴 수 있습니다.

이 스크립트가 하는 일:

- `docker-compose.local-lab.yml`로 컨테이너 3개 실행
- MongoDB mock DB 생성
- 관리자 계정 생성
- 샘플 사용자와 샘플 게임 생성

## 2. 접속

메인 주소:

```text
http://localhost:18080
```

관리자 로그인 주소:

```text
http://localhost:18080/login?uuid=00000000-0000-0000-0000-000000000000
```

관리자 비밀번호:

```text
local-admin-1234
```

기명 사용자 첫 설정 테스트 주소:

```text
http://localhost:18080/login?uuid=11111111-aaaa-1111-aaaa-111111111111
```

무기명 사용자 첫 설정 테스트 주소:

```text
http://localhost:18080/login?uuid=88888888-8888-8888-8888-888888888888
```

또는 첫 화면에서 demo 카드에 보이는 QR을 바로 스캔해도 됩니다.

## 3. 이 환경에서 바로 확인할 수 있는 것

- 일반 사용자 QR 로그인 흐름
- 비밀번호 미설정 guest의 회원가입 흐름
- 관리자 대시보드
- 비밀번호 초기화
- 여분 팔찌 교체
- 게임 등록/수정
- 투표 결과 다운로드

## 4. mock DB에 들어가는 데이터

이 시험장은 백엔드의 `SEED_SAMPLE_DATA=true` 설정으로 데모 데이터를 자동 생성합니다.

예시:

- 관리자 1명
- 샘플 user 여러 명
- 여분 guest 팔찌 여러 개
- 샘플 게임 여러 개

즉, 빈 DB를 직접 채우지 않아도 바로 테스트할 수 있습니다.

## 5. 종료와 정리

시험이 끝나면 아래를 실행하세요.

```bash
./scripts/local-lab-down.sh
```

이 스크립트가 하는 일:

- 로컬 시험장 컨테이너 정지
- 컨테이너 삭제
- mock DB 삭제
- 로컬 시험장용으로 빌드한 이미지 정리

다음에 다시 `./scripts/local-lab-up.sh`를 실행하면 완전히 처음 상태로 다시 시작합니다.

## 6. 자주 하는 질문

### Q. 이걸로 실제 행사 데이터를 넣어도 되나요?

권장하지 않습니다.

이 환경은 시험용입니다. 종료 시 모두 지워질 수 있습니다.

실제 행사 준비는 [서버 빠른 실행](./deploy-quickstart.md)과 [행사 전 게임 데이터 준비](./game-catalog-setup.md)를 기준으로 진행하세요.

### Q. 포트가 이미 사용 중이면 어떻게 하나요?

기본 포트는 아래와 같습니다.

- 프론트: `18080`
- 백엔드: `15001`

이미 사용 중이면 해당 프로세스를 종료하거나, `docker-compose.local-lab.yml`의 포트 값을 바꿔서 사용하세요.
