# 계정 접속 흐름

이 문서는 "참가자가 QR을 찍었을 때 실제로 어떤 화면이 뜨는지"를 설명하는 문서입니다.

## 팔찌 종류

현재 운영 문서 기준으로 팔찌는 두 가지로 생각하면 편합니다.

### 기명식 팔찌

- 보통 `user` 또는 `admin` 역할 계정에 연결됩니다.
- 이름과 소속이 이미 정해져 있습니다.
- 회원가입 화면에 들어가더라도 이름 입력은 보통 잠겨 있습니다.

### 무기명식 팔찌

- 보통 `guest` 역할 계정으로 준비합니다.
- 여분 팔찌로도 사용합니다.
- 비밀번호가 없으면 첫 접속 시 회원가입으로 이동합니다.
- 아직 사용되지 않은 `guest + 비밀번호 미설정 + 투표 이력 없음` 계정은 관리자 화면에서 "여분 팔찌 후보"로 보입니다.

## 참가자 접속 순서

### 1. QR 스캔

- 팔찌 QR은 `/login?uuid=<UUID>` 주소로 이동합니다.

### 2. 사용자 상태 확인

- 프론트 로그인 페이지가 `GET /api/auth/status/:uuid`를 호출합니다.

서버는 아래 정보를 돌려줍니다.

- `uuid`
- `name`
- `club`
- `role`
- `isFirstAccess`

### 3. 분기

#### `isFirstAccess = true`

- 비밀번호가 아직 없는 계정입니다.
- 프론트가 `/signup?uuid=...`로 자동 이동합니다.
- 사용자는 비밀번호를 설정합니다.

쉽게 말하면 "아직 처음 접속하는 팔찌"입니다.

#### `isFirstAccess = false`

- 이미 비밀번호가 있는 계정입니다.
- 로그인 폼이 그대로 표시됩니다.
- 비밀번호를 입력하면 메인 화면으로 이동합니다.

쉽게 말하면 "이미 가입을 마친 팔찌"입니다.

## 회원가입 시 이름이 바뀌는 경우

현재 로직에서는 `guest` 역할일 때만 회원가입 요청에 포함된 이름으로 서버 이름을 바꿉니다.

즉:

- `guest` 계정: 회원가입 시 이름 반영 가능
- `user/admin` 계정: 회원가입 시 이름 변경 불가

또한 프론트 화면에서는 서버에 이름이 이미 있으면 입력칸이 잠깁니다.

따라서 아래 상황은 운영자가 직접 수정해야 합니다.

- 이름이 잘못 등록되어 있는 기명식 팔찌
- 이름이 이미 들어간 guest 팔찌인데 표시 이름을 바꿔야 하는 경우

이때는 관리자 대시보드의 `사용자 정보 수정` 기능을 사용하세요.

## 비밀번호 초기화가 의미하는 것

관리자가 `비밀번호 초기화`를 누르면 서버는 해당 사용자의 `password` 필드를 제거합니다.

그 결과:

- 기존 비밀번호는 더 이상 쓸 수 없습니다.
- 다음 QR 접속 시 회원가입 화면으로 이동합니다.
- 현장에서는 "비밀번호 재설정"보다 "비밀번호를 지운 뒤 다시 설정하게 하기"에 가깝습니다.

즉, 사용자가 다시 처음 비밀번호를 만드는 것과 비슷한 흐름이라고 이해하면 됩니다.

## 관리자 계정 접속

관리자도 별도 로그인 화면이 있는 것이 아니라 일반 로그인 흐름을 사용합니다.

1. `/login?uuid=<ADMIN_UUID>`로 접속
2. 관리자 비밀번호 입력
3. 로그인 후 `/admin`으로 이동

자세한 사용법은 [관리자 대시보드 사용법](./admin-operations.md)을 보세요.
